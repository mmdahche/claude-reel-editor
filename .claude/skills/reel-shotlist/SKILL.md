# reel-shotlist

Turns one script into beats, scenes and modes, so the build can line every graphic up with the
client's real voice. Everything is built from code by default. Paid AI shots are the rare exception
and are never generated by this skill.

## When to use
- A `videos/<client>/<slug>/SCRIPT.md` exists with no `SHOTLIST.md` next to it.
- A transcript has just landed and the draft shot list needs its times snapped to the words.
- The editor changes lines, swaps a scene, or asks "what will this look like".

## When NOT to use
- Judging whether the hook is good, or linting the rules: use `reel-hook-check`.
- Caption wording or style: `reel-captions`. Sound: `reel-audio-gate`.
- Generating any AI image or clip. This skill only lists paid candidates.

## Inputs
- `V=videos/<client>/<slug>` (inside the kit folder): `SCRIPT.md` (one sentence per line), `captures/`.
- `clients/<client>/BRAND.md`: tone, words to avoid, logo rules, comment keyword, CTA, runtime
  target, card-vs-split preference, any "skipped rules" the client approved. Read it first.
- `WORKFLOW.md`: modes, rhythm rules, scene trigger table, shot list schema.
- `demo-synthetic/shotlist.json` (a full example), `compositions/<scene>.html` (each scene's inputs
  are listed at the top of the file).
- After recording: `$V/input/transcript.json` (word times).

## Steps
1. **Header first.** Write the thread (the one subject the hook promises), the target emotion, and
   the common belief versus the contrarian claim from the first two lines. A beat more than one
   step off the thread gets a flag.
2. **Cut beats.** One beat is one sentence, or one clause when the sentence holds a list. Aim for
   2-5 s each (about 2.6 words/s). Tag each beat `HOOK` (first sentence), `LOCKIN` (the 1-3
   sentences after it), then `BODY`, `RECAP`, `STAKES` or `CTA`.
3. **Name the lock-in method**: tease the proof, favourable transformation, contrast, magic box
   (name the framework), objection handling, or bold-claim double-down. If the script has none,
   stop and tell the editor. That is a script problem; visuals will not fix it.
4. **Pick a scene per beat** (scene type in brackets): a list of 2-4 named things on first mention
   [`lineup`]; "vs / which / pick" [`face-off`]; 3+ attributes compared [`table`]; a specific number
   [`stat`]; ordered steps [`steps`]; "here's mine / watch" with a capture [`screen-frame` or proof];
   a quote or DM [`quote`]; the next item of a list [`chapter`, 0.6-1.2 s, then the item's scene];
   a log, commit or bill [`receipt`]; loss, "wrong", "every month" [overlay `stamp`]; a one-word
   punch [overlay `word-slam`, at most 2 per video]; the ask [`cta`, or overlay `cta-footer` when
   the ask is not a comment keyword]; the first line [`hook-title`, `*word*` = the one serif accent
   word]. If two triggers hit, the more specific wins. Real footage beats a graphic for the same idea.
5. **Opening (hard rule).** Frame 0 shows b-roll and the face together: an A2 split (footage on top,
   face below) or an A beat with a scene, with the hook title over it. Never a title-only card,
   never a bare face. Then a full-face B beat for the lock-in inside the first 5-8 s.
6. **Modes and rhythm.** Something in the picture changes every 2-4 s (captions do not count).
   Switch mode every 1-2 sentences. Max holds: A/A2 6 s, B 4 s, C 5 s (table and CTA 8 s). Never
   two B beats in a row unless it is a deliberate B-B-B punch of 1.2 s or less each. Group A and A2
   into runs with B as the hinge. Hard cuts between modes, never dissolves. End on the ask.
7. **Real footage: card or split, per beat.** `"layout": "split"` for the first reveal of real
   footage and for anything the viewer must read on a phone or screen. `"layout": "card"` when the
   stage graphic carries the point. The client may override any beat (check BRAND.md). Raw phone
   screen recordings go in a phone mockup (`screen-frame`, `device: "phone"`), never full-bleed.
   Screen and UI captures get `"grade": false`; camera footage keeps the brand grade.
8. **Captures.** Match each footage beat to a file in `$V/captures/`. List every missing capture,
   and the hold / look cues per beat ("beat 4: open palm toward the panel, hold 1 s"), in
   `$V/NEEDS.md` for the client before they record.
9. **Paid-shot gate.** Default 0 paid shots. Only list a candidate if ALL hold: it is a story image,
   not a fact; no capture or HyperFrames motion can show it within an hour; it lands in the first
   10 s or the stakes beat; the prompt has no text or UI. Write candidates and their estimated cost
   in SHOTLIST.md for the editor. Never call a paid tool or paid API without the editor's explicit
   yes for that video.
10. **SFX tags.** Put `"tag"` on every beat (the audio pass reads it). `"sfx": false` mutes a beat;
    `"sfx": [{"at": 12.3, "cue": "pop"}]` adds a hand cue (whoosh, tick, pop, thud, keys).
11. **Write the files.** Copy an existing file to `.bak-<date>/` beside it before overwriting.
    - `$V/SHOTLIST.md`: header from step 1, lock-in method, runtime estimate, paid shots (normally
      0), then a table: `# | line | tag | scene | mode | layout | capture | start-end | note`.
    - `$V/input/shotlist.json`: schema in WORKFLOW.md. Media paths are relative to the kit folder
      (e.g. `videos/<client>/<slug>/input/face.mp4`). Before recording, times are estimates. After
      `transcript.json` exists, snap each beat to its first and last word, keep beats back to back
      from 0, and make the last `end` equal `duration`.
12. **Build check** (after the transcript exists):
    `node scripts/build.mjs --input $V/input --brand clients/<client>/brand.json`. Fix every
    `ERROR`; read every `warning`, especially unknown scene inputs and the `real-footage layout:`
    line. Then run `reel-hook-check`.

## What to tell the editor (plain English)
Up to five sentences: the thread and lock-in method, beat count and estimated length, how many
beats use real footage, what the client still needs to send (or "nothing"), and that paid shots
are zero (or the one candidate and its cost, for their OK). The table lives in SHOTLIST.md.

## Checklist
- [ ] BRAND.md was read; thread, emotion, belief vs claim and lock-in method are named (or a
      missing lock-in is flagged).
- [ ] Frame 0 is footage + face; a B lock-in beat lands early; no two B in a row; holds in limits.
- [ ] Every real-footage beat has `layout` card or split; UI captures have `grade: false`.
- [ ] Paid shots are 0, or listed for approval. Nothing was generated.
- [ ] `build.mjs` passes. `reel-hook-check` runs next.
